From camera calibration to 3D neural scene representation.

Course: CS180 – Intro to Computer Vision and Computational Photography
Author: Jennie Dong
Semester: Fall 2025

Overview

In this project I implement a full Neural Radiance Field (NeRF) pipeline in PyTorch, starting from camera calibration and pose estimation and ending with novel-view rendering of both the provided LEGO scene and my own real object.

The implementation follows the project specification and uses the same overall architecture and training strategy as the student reference ex2: a 2D neural field in Part 1 and a 3D NeRF-style MLP in Part 2, trained with volumetric rendering on multi-view images.

This page walks through each part of the project, explains the key ideas, and shows qualitative and quantitative results along the way.

  • Part 0: Calibrate camera, capture a 3D scan of my object, estimate poses, and build a dataset.
  • Part 1: Fit a neural field to a single 2D image using positional encoding.
  • Part 2: Extend to a full NeRF with ray sampling, volume rendering, and novel-view synthesis.
  • Part 2.6: Train NeRF on my own captured object using the same pipeline.

Part 0 – Camera Calibration and 3D Scanning

The goal of Part 0 is to turn my phone into a calibrated pinhole camera and to produce a clean multi-view dataset of a real object, complete with camera-to-world poses, undistorted images, and a single consolidated .npz file for NeRF training.

0.1 – Calibrating My Camera

I first captured around 70 images of printed 4×4 ArUco markers at a fixed zoom level (1.0×). The tags were viewed from a variety of angles, distances, and positions in the frame. For each calibration image, I detected all visible ArUco tags, extracted their corner pixel coordinates, and matched them with known 3D points on the tag plane.

Accumulating 2D–3D correspondences across all valid frames, I ran OpenCV’s calibration routine to estimate the intrinsic matrix K and distortion coefficients (radial and tangential). These intrinsics are used later for pose estimation, undistortion, and reconstructing the NeRF camera matrix for my own dataset.

Calibration summary:

  • 69 valid calibration images (tag detected)
  • Resolution after downsampling: 1200 × 1600
  • RMS reprojection error: 0.9 px
  • Estimated intrinsics matrix K and distortion vector d
After calibration, I verified that straight edges in the scene appear much straighter in the undistorted images, confirming that radial distortion is being corrected and that the recovered K is consistent with the physical camera.

0.2 – Capturing a 3D Object Scan

For my custom NeRF scene, I chose a small labubu placed on a table next to a printed ArUco tag (ID 0). I then walked around the object and captured 75 photos at different azimuth and elevation angles, making sure that:

  • the labubu is always visible and roughly centered,
  • the ArUco tag is visible in every frame, and
  • lighting is reasonably uniform with no motion blur.

I tried to roughly follow a spherical trajectory around the toy so that the final NeRF would see the object from a rich set of viewpoints rather than just a single side.

0.3 – Estimating Camera Pose (PnP)

Using the calibrated intrinsics and distortion parameters, I then estimated the camera pose for each object image using a Perspective-n-Point (PnP) formulation. For each frame:

  1. Detect the single ArUco tag and extract its 2D corner pixel coordinates.
  2. Define the corresponding 3D corner positions on the tag plane in world coordinates.
  3. Solve for rotation and translation with a PnP algorithm, producing a world-to-camera transform.
  4. Invert this transform to obtain a camera-to-world matrix c2w that NeRF expects.

I saved each c2w along with the associated image path in poses/pose_XXX.npz files. I also visualized the resulting camera frustums using viser, confirming that the cameras form a ring around the object at varying heights with consistent orientation.

0.4 – Undistorting Images and Creating the Dataset

Finally, I undistorted each object image using the previously estimated K and d. To handle small resolution mismatches from the iPhone pipeline, I resize all undistorted images to a common target resolution and adjust the intrinsics accordingly so that the focal length and principal point remain consistent with the resized images.

I then split the valid frames into training, validation, and test sets and packed everything into a single .npz file used later for Part 2.6.

Saved dataset (example structure):

  • images_train – undistorted training images (Ntrain, H, W, 3)
  • c2ws_train – camera-to-world matrices for training frames
  • images_val, c2ws_val – validation set
  • images_test, c2ws_test – test trajectory for novel views
  • focal, K, dist, H, W

Part 1 – Fitting a Neural Field to a 2D Image

Before moving to full 3D radiance fields, I first implemented a 2D neural field that learns a continuous mapping from image coordinates to RGB colors. This part is a smaller sandbox to validate positional encoding, MLP design, optimization, and PSNR measurement.

1.1 – Setup and Model Design

Each pixel in the target image is represented by its normalized coordinate (x, y) ∈ [0,1]². I apply sinusoidal positional encoding (PE) to lift the input into a higher-dimensional feature space:

  • Concatenate raw coordinates with multiple sine and cosine functions at exponentially growing frequencies.
  • Use L = 10 frequency bands, resulting in a 42-dimensional encoded input.

The encoded coordinates are fed into a small fully connected network with ReLU activations and a final sigmoid layer that predicts RGB values in the range [0,1]. I train this model with mean squared error between predicted and ground-truth colors using Adam, and track PSNR as the main quality metric.

1.2 – Training on Provided and Custom Images

At each iteration, I randomly sample a batch of pixels from the image, encode their coordinates, and supervise the network with the corresponding RGB values. I track PSNR as a function of iteration and periodically render the full predicted image to visualize convergence on both the staff-provided image and one of my own photos.

1.3 – Hyperparameter Study

I varied both the network width and the positional encoding frequency to see their effect on reconstruction:

  • Widths: 64 and 256 hidden units.
  • PE frequency levels: L = 4 and L = 10.

Lower PE frequency and narrow networks tend to over-smooth the image, while higher frequency and wider networks capture sharper edges and fine texture at the cost of more parameters and training time.

Takeaway: a coordinate-based MLP with positional encoding can memorize a 2D image with surprisingly high fidelity, hinting at how NeRF can represent full 3D scenes as continuous functions.

Part 2 – Neural Radiance Field from Multi-view Images

In Part 2, I extend the 2D neural field to a full 3D NeRF that reconstructs a scene from multiple calibrated views. The model predicts, for each 3D point and viewing direction, a density and a view-dependent color that are then integrated along camera rays via volume rendering.

2.1 – Creating Rays from Cameras

Given the camera intrinsics K and a camera-to-world matrix c2w for a particular image, I generate a ray for each pixel:

  1. Convert pixel coordinates (with a 0.5 offset to hit pixel centers) to a unit-depth point in camera coordinates using the inverse of K.
  2. Transform that point into world coordinates using c2w.
  3. Define the ray origin as the camera center (c2w translation) and the ray direction as the normalized vector from origin to the transformed point.

I implemented this in a batched form so that many pixels from many images can be processed efficiently on the GPU.

2.2 – Sampling Rays and Points

To feed the NeRF, I sample a batch of rays and then discretize each ray into a sequence of 3D points:

  • Ray sampling: Flatten all pixels over all training images, randomly choose a subset, and map them to ray origins and directions.
  • Depth sampling: For each ray, sample 64 depth values uniformly between near = 2.0 and far = 6.0, and optionally add stratified jitter during training.

Each sampled 3D point, together with its ray direction, is passed to the NeRF MLP, which outputs the local density and color used in the volume rendering step. During evaluation, I disable jitter to obtain deterministic, smooth renders.

2.3 – Data Pipeline for Multi-view Rays

I wrap the LEGO images, intrinsics, and camera poses in a custom dataset class that:

  • stores all RGB images normalized to [0,1],
  • precomputes pixel grids and associated indices,
  • and, on request, returns a batch of ray origins, ray directions, and target pixel colors.

This dataset is reused for both the LEGO scene and my own captured dataset in Part 2.6, so all later components (sampling, NeRF, volume rendering) can treat the two scenes in a unified way.

2.4 – NeRF Network Architecture

The NeRF network follows the standard architecture used in the project and in student ex2:

  • 8 fully connected layers with width 256 in the main “position” tower.
  • A skip connection that concatenates the encoded position back into the hidden features halfway through.
  • Sinusoidal positional encoding with high-frequency bands for positions (Lx = 10) and lower-frequency bands for directions (Ld = 4).
  • Two output branches:
    • Density head: produces σ(x) ≥ 0 via a ReLU.
    • Color head: conditions on both features and encoded view direction, outputting RGB in [0,1] via a sigmoid.

I kept the architecture identical to the reference implementation so that I could focus on the geometry and data-processing aspects of the project.

2.5 – Volume Rendering and LEGO Results

Given per-sample densities σi, colors ci, and a constant step size Δt along each ray, I implement discrete volume rendering:

  • Convert densities to opacities αi = 1 − exp(−σi Δt).
  • Accumulate transmittance Ti via prefix products over (1 − αj).
  • Compute weights wi = Ti αi and form the final pixel color as a weighted sum of ci.

All of these operations are vectorized in PyTorch using cumprod and cumsum for efficiency and to keep gradients stable. A small epsilon is added inside logs and products to avoid numerical issues.

On the LEGO dataset, I train the NeRF for 3000 iterations, sampling 10,000 rays per iteration and 64 points per ray, using the near–far range [2.0, 6.0]. I periodically render validation views and compute PSNR.

2.6 – Training NeRF with My Own Data (Labubu)

Finally, I train NeRF on the custom dataset collected in Part 0. The pipeline is exactly the same as for the LEGO scene; I only change dataset-specific hyperparameters such as near/far bounds and, optionally, the model width and number of samples per ray to better fit this small, close-range tabletop scene.

Capture summary: 75 images of a labubu with an ArUco tag on a table, split into training, validation, and test sets. The scene is physically small and relatively close to the camera, so the optimal depth range is much narrower than for the LEGO dataset.

2.6.1 – Hyperparameters and Engineering Choices

  • Near/Far: near = 0.01, far = 0.5, tuned to focus samples on the toy and its immediate surroundings.
  • Samples per ray: 128 (increased to better capture real-world details without excessive noise).
  • Model width: 512 (for higher capacity on the real scene and high-frequency texture).
  • Iterations: about 40,000 training steps, with periodic checkpointing and offline rendering after training.
  • Rays per iteration: 5,000–10,000, chosen to balance convergence speed with GPU memory.

Compared to LEGO, this configuration trades more compute and a larger model for better reconstruction quality on my own data, while keeping VRAM usage reasonable by limiting rays per iteration.

Bells & Whistles – Depth Rendering

For the bells & whistles component, I extended the volume rendering pipeline so that it produces a per-pixel depth map alongside the usual RGB image. Instead of only compositing colors along each ray, I re-use the same NeRF weights to also aggregate depth, so the RGB image and the depth map are perfectly consistent with each other.

The procedure mirrors the standard NeRF rendering:

  • First, I compute the per-sample interval Δt from the sampled depth values t along each ray and convert densities σi into opacities αi = 1 − exp(−σi Δti).
  • Next, I form the transmittance Ti using a prefix product over (1 − α), and then define the weights wi = Ti αi, exactly as in the RGB compositor.
  • The RGB color is obtained as usual by a weighted sum of the predicted colors: rgb = Σ wi · ci.
  • For depth, I keep the same weights but instead composite the sample depths: depth = Σ wi · ti.

I also accumulate the total opacity acc = Σ wi to build a simple foreground mask and visualize inverse depth (disparity) instead of raw depth. The disparity values are normalized into [0,1] and passed through a mild gamma curve to boost contrast, which makes nearby surfaces stand out more clearly.

Using this extended renderer, I generate depth maps for all test camera poses in c2ws_test and assemble them into a depth-only GIF that orbits around the LEGO scene. The result highlights the underlying 3D structure captured by the NeRF and provides a complementary geometric view in addition to the RGB renderings.
